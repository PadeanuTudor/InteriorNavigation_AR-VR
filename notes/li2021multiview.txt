Title: Accurate Indoor Localization Using Multi-View Image Distance
Author(s): Xinyun Li, Ryosuke Furuta, Go Irie, Yukinobu Taniguchi (Tokyo University of Science, The University of Tokyo, NTT Communication Science Laboratories)
Group: Visual positioning against a 3D map / image database
Published: IEVC 2021, paper 3A-2 (open access, author-hosted camera-ready PDF)


WHAT IT DOES
I read the whole paper (short workshop paper). The problem: indoors, one photo is rarely enough to pick out the right place, because walls, desks and floors look alike. The fix is to use four photos as the query (front, back, left, right, at 90 degree steps while the user turns on the spot) and to compare them as a set with the reference sets stored at about 1 m intervals, which were also captured in four directions. Image features are 2048-dimensional GeM-pooled descriptors from a ResNet152 trained on Google Landmarks 2018 (with whitening, pooling parameter 3). The multi-view distance between the query set and a reference set is the minimum, over all permutations of the four views, of the sum of per-view Euclidean distances (so the order in which the photos were taken does not matter), and the location is the reference set with the smallest distance.
Evaluation by "one-metre-level accuracy" (share of queries located within 1 m). TUS Library dataset (their own; 3,358 m2, 159 reference locations, 42 query locations, 480x640 images, iPhone SE for references and iPhone 8 Plus for queries): SIFT + geometric verification 47.6% (about 132 s per query), GeM single view 61.3% (0.76 s), multi-view with 1/2/3/4 directions 61.3% / 71.4% / 81.0% / 85.7% (0.65 s up to 3.95 s). West Coast Plaza shopping-mall dataset (15,000 m2, 316 reference and 78 query locations): their method with 4 directions 84.0% vs. 79.9% for Graph Location Networks (Chiou et al. 2020); 1/2/3 directions gave 73.1% / 78.2% / 80.8%. The failure case is a place where all four views contain many similar-looking images.


RELEVANT TO MY WORK
It is a clean quantitative demonstration that the ambiguity problem can be reduced by looking around a bit, and it gives a measurable cost: each extra view adds both accuracy and delay. For my app I could use consecutive video frames or ask the user for a quick pan at the start, and treat it as the fallback when a single landmark is not unique enough. It also uses a modern learned global descriptor, so it is a closer baseline for "image retrieval" than the SIFT-era papers.


USE IT FOR
- A baseline for retrieval-based localisation with a modern global descriptor (GeM pooling) and the 1 m accuracy metric.
- Multi-view / multi-frame queries to disambiguate similar places.
- A comparison point against Graph Location Networks on the public West Coast Plaza dataset.
- The accuracy-vs-number-of-views trade-off as a design parameter.


CAVEATS
- Four photos per query is inconvenient (the authors say so and list reducing it as future work), and the 4-view query takes about 4 s.
- Output is only the nearest reference location, not a heading, so I would still need something else to orient an arrow. Accuracy is limited by the 1 m spacing of the reference locations.
- Small query sets (42 and 78 locations); no people moving in the images, and the query orientation is assumed to match the reference capture. Whole-building reference photo surveys are needed.
- Reported timings are for their machine; I do not know whether this runs on a phone. It is a 4-page workshop paper, so the detail is thin.
