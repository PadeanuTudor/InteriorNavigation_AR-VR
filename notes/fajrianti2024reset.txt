Title: A User Location Reset Method through Object Recognition in Indoor Navigation System Using Unity and a Smartphone (INSUS)
Author(s): Evianita Dewi Fajrianti, Yohanes Yohanie Fridelin Panduman, Nobuo Funabiki, Amma Liesvarastranta Haz, Komang Candra Brata, Sritrusta Sukaridhoto (Okayama University, Universitas Brawijaya, PENS Surabaya)
Group: Landmark / text / object recognition (follow-up to an AR-arrow system)
Published: Network 4(3), 295-312, 2024 (open access, CC BY)


WHAT IT DOES
I skimmed the abstract and the section outline; the full text did not come through when I opened it, so this note is abstract-level. It is the follow-up to INSUS. In INSUS the user's location is reset by scanning a QR code, which means someone has to stick QR sheets all over the building. Here the authors replace that with the signs that already exist (room numbers, room names, floor numbers). The user takes a photo of a sign with the phone, YOLOv8 detects the sign in the image, PaddleOCR reads the text, and the text is matched against a Room Database using Levenshtein distance (so small OCR errors still match). They tested it in two buildings at Okayama University. Reported: YOLOv8 mAP@0.5 of 0.995 and mAP@0.5:0.95 of 0.978; PaddleOCR averaged a character error rate below 10%; and the YOLOv8 + PaddleOCR combination cut the execution time by 6.71 s compared with their previous method.


RELEVANT TO MY WORK
This is almost exactly my "camera sees something unique and knows where I am" idea, bolted onto an AR-arrow app. Room signs act as the landmarks, so no markers have to be installed. It also shows a concrete, current toolchain (YOLOv8 + PaddleOCR + fuzzy string matching) that I could reproduce, and it plugs into the same SLAM-plus-arrow pipeline as the original INSUS paper.


USE IT FOR
- Direct design pattern for a landmark-based position reset that replaces QR codes.
- Choice of models: detector (YOLOv8) to find the sign, OCR (PaddleOCR) to read it, edit distance to match against a room list.
- Evaluation ideas: detection mAP, OCR character error rate, end-to-end execution time.
- Pair it with OCRAPOSE II (sadeghi2017ocrapose2), which also uses text as landmarks but estimates distance and angle from the sign.


CAVEATS
- Abstract only: I do not know the details of the dataset size, phones used, or how often a reset succeeds in practice.
- The position is only "at this sign". A sign gives me a place, not a heading, so I would still depend on SLAM/ARCore between resets.
- Needs signs with legible text. Corridors without signs, or signs with identical text (for example repeated floor numbers or room names on different floors), would be ambiguous.
- The 6.71 s improvement is relative to their own previous method, not to other published systems.
